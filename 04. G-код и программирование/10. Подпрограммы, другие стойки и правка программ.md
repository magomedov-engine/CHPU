## 1. Подпрограммы: M98 и M99

**Подпрограмма** — отдельная программа, которую основная программа **вызывает** (один или несколько раз). Удобно для повторяющихся элементов: одинаковые карманы, проходы по глубине, группы отверстий.

```gcode
O0010 (MAIN)
...
G00 X50. Y30. Z2.
M98 P1234 L4          (вызвать O1234 четыре раза)
G90 G00 Z50.
M30

O1234 (SUB - 1 PASS 2MM DEEPER)
G91 G01 Z-2. F200     (на 2 мм глубже — в приращениях)
G90 G41 D5 X... Y...  (контур)
...
G40 ...
M99                   (возврат в основную программу)
```

| Код | Значение |
|---|---|
| **M98 P1234** | Вызвать подпрограмму O1234 |
| **L4** (или **P41234** на некоторых Fanuc) | Повторить 4 раза |
| **M99** | Конец подпрограммы — возврат в основную |
| **M99** в основной программе | Бесконечный повтор программы с начала (на прутковых автоматах) |

> [!info] Локальные подпрограммы
> Siemens и некоторые стойки позволяют вызывать подпрограмму **по имени** (`L1234` или `CONTOUR1`) и писать её в конце той же программы. Haas — `M97 P1000` вызывает подпрограмму с метки N1000 внутри той же программы.

## 2. Переменные (макропрограммирование) — обзор

На Fanuc есть **Custom Macro B**: переменные `#1`, `#100`, арифметика и условия. Это уровень наладчика/программиста, но такие программы встречаются (например, для семейства похожих деталей).

```gcode
#1 = 5.              (глубина кармана)
#2 = 2.              (шаг по глубине)
#3 = 0               (текущая глубина)
WHILE [#3 LT #1] DO1
  #3 = #3 + #2
  IF [#3 GT #1] THEN #3 = #1
  G01 Z-#3 F200
  M98 P1234
END1
```

| Переменные | Назначение |
|---|---|
| **#1–#33** | Локальные (внутри макроса) |
| **#100–#199** | Общие, **сбрасываются** при выключении |
| **#500–#999** | Общие, **сохраняются** при выключении |
| **#5000+** | Системные: текущие координаты, корректоры и т. д. |

> [!warning] Не трогать без понимания
> Переменные #500+ часто используются производителем или наладчиком (счётчики деталей, настройки щупа). Изменение «на глаз» может нарушить работу. Это не для оператора.

## 3. Другие стойки: Siemens и Heidenhain

Основа (G0, G1, G2, G3, координаты, M-коды) похожа, но есть важные отличия.

### Siemens Sinumerik

```text
; Комментарий после точки с запятой
N10 G17 G90 G54 G71        ; G71 у Siemens = миллиметры!
N20 T="DRILL_D9" D1        ; инструмент по имени, D1 — корректор
N30 M6
N40 S3500 M3
N50 G0 X10 Y10 Z50
N60 CYCLE83(50,0,3,-19,,,4,1,0,0,1,1)   ; глубокое сверление: отвод 50, Z0, безоп. 3, до -19, клевок 4
N70 G2 X40 Y40 CR=20        ; дуга через CR= (радиус)
N80 G96 S200 LIMS=2500      ; скорость резания и ограничение
N90 M30
```

### Heidenhain (Klartext)

```text
0 BEGIN PGM PLATE MM
1 TOOL CALL 5 Z S8000        ; инструмент 5, ось Z, обороты
2 L Z+50 R0 FMAX M3          ; FMAX — ускоренно
3 L X+50 Y+30 R0 FMAX
4 L Z-5 F300
5 L X+50 Y+20 RL F800        ; RL — коррекция слева (как G41)
6 L X+65                     ; по прямой до начала скругления
7 CC X+65 Y+25               ; центр окружности
8 C X+70 Y+25 DR+            ; дуга против часовой (DR+)
9 CYCL DEF 200 DRILLING ...  ; цикл сверления
10 END PGM PLATE MM
```

| Что | Fanuc | Siemens | Heidenhain |
|---|---|---|---|
| Комментарий | `( )` | `;` | `;` |
| Миллиметры | G21 | **G71** (!) | MM в заголовке |
| Ускоренно | G00 | G0 | `FMAX` |
| Инструмент | T05 M06 | T="NAME" / T5 D1, M6 | TOOL CALL 5 |
| Длина | G43 H05 | автоматически по D | автоматически |
| Коррекция радиуса | G41 / G42 D | G41 / G42 | RL / RR |
| Дуга радиусом | R | CR= | CR / CC + C |
| Цикл сверления | G81–G89 | CYCLE81–CYCLE89 | CYCL DEF 200–209 |
| Ограничение оборотов | G50 S | LIMS= | — |

> [!warning] Ловушка: G71 у Siemens
> У Siemens **G71 — это миллиметры** (G70 — дюймы), а у Fanuc-токарного **G71 — черновой цикл**. Один и тот же код — совершенно разное значение.

> [!tip] 💬 Скажи на собеседовании
> «Я изучал G-код на примере Fanuc. Знаю, что у Siemens циклы называются CYCLE, у Heidenhain свой язык Klartext, но логика одинаковая: инструмент, обороты, нуль, коррекции, траектория. Переучиться на другую стойку — вопрос нескольких дней».

## 4. ⭐ Что оператор может менять в программе

> [!info] Общее правило
> **Программа — документ технолога.** Оператор не меняет траекторию и размеры. Любые правки — **только с разрешения** наладчика/мастера/технолога и с записью (или по правилам предприятия).

| Изменение | Можно ли оператору | Комментарий |
|---|---|---|
| **Корректоры износа** (на экране OFFSET) | ✅ Да — основная работа оператора | Программу при этом не трогают |
| **Корректор подачи/оборотов на пульте** | ✅ Да, в разумных пределах | Временная подстройка при вибрации |
| **F и S в программе** | ⚠️ По согласованию | Если корректор постоянно стоит на 80 % — пусть технолог поправит программу |
| **M01 / блок-пропуск `/`** | ⚠️ По согласованию | Удобства контроля |
| **Номер G54 / H / D** | ⚠️ Только по указанию наладчика | Ошибка = авария |
| **Координаты траектории, глубины** | ❌ Нет | Задача технолога. «Подкрутить размер» — через корректор, не через координаты |
| **Удаление/вставка строк с движениями** | ❌ Нет | Модальность может изменить поведение следующих строк |

> [!warning] Как правильно править (если разрешили)
> 1. **Сохранить копию** исходной программы.
> 2. Менять **минимально**, понимая модальность.
> 3. После правки — **графика** и **покадровый** запуск правленого участка.
> 4. Сообщить технологу, чтобы изменение попало в архивную версию — иначе в следующий раз загрузят старую программу.

## 5. Перезапуск программы с середины

Сломалась пластина на 5-м инструменте — не запускать же всё сначала. Перезапускают **с начала блока этого инструмента**.

> [!tip] Правильная точка перезапуска
> Перезапуск — **с кадра смены инструмента** (например, `N450 T5 M06`), а не с середины траектории. В этом кадре и следующих за ним задаются **все** нужные режимы: инструмент, G54, обороты, M03, G43 H, СОЖ. Если начать с середины — станок может не включить шпиндель, не взять коррекцию длины и т. п.

На стойках есть функции **поиска кадра** и **перезапуска** (у Fanuc — Program Restart / поиск номера N), которые «проматывают» программу и восстанавливают модальные режимы. Как ими пользоваться на конкретном станке, покажет наладчик.

> [!danger] После перезапуска
> Первые кадры — **покадрово**, ускоренный ход **на 25 %**, рука на **Feed Hold**. Проверить на экране: правильный инструмент, обороты, G54, длина H.

## 6. Проверка программы перед запуском

| Способ | Что даёт |
|---|---|
| **Симуляция в CAM** | Программист проверяет столкновения на 3D-модели — до станка |
| **Графика на стойке** (GRAPH) | Прорисовка траектории — видно ошибки формы, лишние движения |
| **Machine Lock** + графика | Программа «выполняется» без движения осей — проверка синтаксиса и пределов хода |
| **Dry Run** (холостой прогон) над деталью | Все перемещения на подаче корректора; инструмент поднят над деталью (сдвиг Z) — проверка траектории «в воздухе» |
| **Single Block + 25 % ускоренного** | Первый реальный проход с полным контролем |

Подробно о безопасном первом запуске — [[06. Система ЧПУ и пульт оператора]].

## 7. Итоги урока

> [!summary] Запомни
> 1. **M98 P… L…** — вызов подпрограммы, **M99** — возврат.
> 2. Переменные **#1, #100, #500** — макропрограммирование; без понимания не трогать.
> 3. Siemens: `;`, **G71 = мм**, CYCLE8x, CR=, LIMS=. Heidenhain: L, FMAX, RL/RR, CC/C, CYCL DEF.
> 4. Оператор меняет **корректоры**, а не координаты. Правки программы — только по согласованию, с копией и проверкой.
> 5. Перезапуск — с **кадра смены инструмента**, покадрово, 25 %.
> 6. Проверка: **графика → Machine Lock / Dry Run → Single Block**.

## ❓ Проверь себя

> [!question]- 1. Что делает `M98 P2000 L3`?
> Вызывает подпрограмму O2000 три раза подряд.

> [!question]- 2. Что означает G71 у Siemens и у Fanuc-токарного?
> У Siemens — миллиметры; у Fanuc-токарного — черновой цикл продольного точения.

> [!question]- 3. Размер ушёл на 0,03. Править координату в программе?
> Нет — внести коррекцию в износ инструмента. Координаты траектории — зона ответственности технолога.

> [!question]- 4. С какого кадра перезапускать программу после поломки инструмента?
> С кадра смены этого инструмента (T… M06), где заново задаются все режимы.

> [!question]- 5. Чем Dry Run отличается от Machine Lock?
> Dry Run — оси реально двигаются (на подаче корректора), обычно над деталью. Machine Lock — оси стоят, программа выполняется «на экране».

> [!question]- 6. Как у Heidenhain обозначается ускоренный ход и коррекция слева?
> FMAX и RL.
